# Map Roulette — 设计理解与评价

## 这是什么

Map Roulette 是一个**随机国家选择器**，核心交互：点 SPIN → 国家列表像老虎机滚动 → 减速停下 → 左侧列表高亮 + 右侧地图高亮，同步、即时、直接。

不是实用工具，是一个**纯玩的小装置**。但它的技术含量藏在"玩"里。

---

## 三个子系统

```
┌─────────────────────────────────────────────────────┐
│  [国家列表 / 轮盘]      │  [SVG 世界地图]            │
│                         │                           │
│  Afghanistan            │   ○ ○ ●(高亮) ○ ○         │
│  Albania          ←──── │                           │
│  ▶ Algeria ◀ (选中)     │                           │
│  Andorra                │                           │
│  Angola                 │                           │
│                         │                           │
├─────────────────────────┴───────────────────────────┤
│  [详情面板]  🇩🇿  Algeria  |  首都 | 人口 | 面积...  │
└─────────────────────────────────────────────────────┘
```

**子系统 1：列表轮盘（Slot Machine）**
这是整个 effect 的情绪核心。它不是一个普通的 `<select>` 下拉，而是借用了老虎机 / gacha 的心理机制：
- 快速滚动 → 制造随机感和期待感
- 减速停下 → 制造"揭晓"的仪式感
- 高亮定格 → 给出明确答案

**子系统 2：SVG 世界地图**
地图是空间锚点，给"随机"加上地理维度的意义。颜色高亮是最直接的视觉反馈，ZOOM 功能让地图从"全局索引"变成"局部聚焦"。

**子系统 3：详情面板**
信息层。选中之后展示国旗、人口、首都等，把随机结果变成可读内容，延长停留时间。

---

## 核心设计逻辑

### 为什么这个组合有效

地图 + 轮盘，这两个元素单独都很无聊：
- 单独的轮盘：无聊，结果没有意义
- 单独的地图点击：没有随机感，只是查地图

**组合之后**：轮盘负责制造悬念，地图负责赋予空间意义。一个给情绪，一个给认知。这是这个 effect 最聪明的地方。

### 节奏感是关键

Spin 动画的节奏直接决定体验质量：

```
快速滚动（0.0s - 0.8s）→ 减速（0.8s - 1.4s）→ 弹性收尾（1.4s - 1.6s）→ 定格
```

减速曲线不能是线性的，要用 `ease-out` 或贝塞尔曲线，让停止的那一刻有"咔哒"的质感。如果用线性减速，体验会非常廉价。

## 技术架构分析

| 层 | 技术 | 核心挑战 |
|---|---|---|
| 地图渲染 | SVG + GeoJSON → d3-geo 投影 | 坐标系转换，路径压缩 |
| 国家数据 | JSON（~250 条） | 国旗 URL、元数据字段规范 |
| 轮盘动画 | CSS scroll-behavior 或 JS 手动控制 translateY | 缓动曲线的手感 |
| 高亮同步 | 状态驱动（selectedCountry → 地图 fill + 列表 scrollTo） | 时序耦合 |
| Zoom | SVG viewBox 动画 | 边界框计算，过渡平滑 |

GeoJSON 是关键数据源。世界地图的 GeoJSON 有多个精度版本，需要权衡文件大小和形状精度：
- `110m`：文件小（~100KB），形状粗糙，适合 overview
- `50m`：文件中（~400KB），推荐用这个
- `10m`：文件大（~4MB），不适合 web

## 设计评价

### 做得好的地方

**1. 情绪设计到位**
Spin 的"快速 → 减速 → 定格"三段式是标准的老虎机情绪弧线，用在地图选择器上产生了一种荒诞而好玩的反差。这个创意本身就值得实现。

**2. 双通道反馈**
列表高亮 + 地图高亮同时发生，视觉上形成左右呼应。用户不需要主动"去找"选中的是哪个国家，答案同时出现在两个位置，认知负担极低。

**3. 信息密度克制**
Spin 完成后才展示详情面板，而不是在轮盘滚动时就显示。这个时序选择是对的——滚动时显示信息会打断悬念感。

### 可以做得更好的地方

**1. 地图高亮太"硬"**
直接切换 fill 颜色没有过渡，在连续多次 Spin 的场景下，高亮的切换会显得很粗糙。加一个 100-150ms 的颜色淡入过渡会好很多。

**2. 列表和地图的情感断层**
列表轮盘有动画节奏，地图是瞬间切换，两者的"速度感"不匹配。地图高亮应该比轮盘停下慢一拍（延迟 200ms 再出现），模拟"揭晓"感。

**3. ZOOM 功能的可发现性低**
ZOOM 按钮是在选中之后才应该使用的，但它和 WORLD 按钮平级排列，初次使用者不一定知道什么时候该点。可以考虑在选中之后才让 ZOOM 按钮变成 active 状态。

**4. 详情面板缺乏层次**
信息都平铺展开，没有主次。国旗 + 国家名应该是第一视觉层级，人口/面积等是次要信息，排版上要体现这种差异。

---

## 这个 Effect 在这个项目里的位置

按 CLAUDE.md 的分类体系，它属于 **click** 类别——主触发是点击 SPIN 按钮。

但它是一个**复合 effect**：Spin 是 click，地图高亮是 click 的反馈，Zoom 是连续交互，详情展示是状态变化。这不是单一动效，而是一个迷你交互装置。

这也意味着它的开发量比单一动效大 3-4 倍，需要按阶段分解来控制复杂度。

---

## 一句话

> Map Roulette 用老虎机的情绪机制把"选一个国家"这件无聊的事变成了一个有期待感的游戏。它的技术门槛在 GeoJSON 地图渲染和 Spin 的缓动曲线，设计门槛在列表与地图的时序协同。
